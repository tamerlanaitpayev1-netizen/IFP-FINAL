# Презентация проекта ArenaQuiz (Структура слайдов для защиты)

## Слайд 1. Титульный лист
- **Название проекта:** ArenaQuiz — Платформа для интерактивных викторин в реальном времени с серверным анти-чит контролем
- **Участники команды:**
  - **Тамерлан** — Backend & Real-Time Architect (ASP.NET Core 10, SignalR Hub, Server Timers, EF Core SQLite, RBAC, xUnit)
  - **Диас** — Frontend & Blazor WASM Engineer (Blazor WebAssembly, State Container, Reusable/Templated Components, Responsive UI, WebAudio, bUnit)
- **Стек:** .NET 10, Blazor WebAssembly, ASP.NET Core SignalR, Entity Framework Core + SQLite, xUnit + bUnit

---

## Слайд 2. Актуальность, цель и задачи
- **Актуальность:** Дистанционное и гибридное обучение требует мгновенной обратной связи на занятиях без установки нативных мобильных приложений. Бесплатные тарифы коммерческих платформ ограничивают число участников (10–40 человек), не дают выгружать детальные логи бесплатно и не поддерживают вставку кода или кастомные режимы.
- **Цель проекта:** Разработать кроссплатформенную веб-систему проведения викторин в реальном времени на базе Blazor WebAssembly и SignalR с полной изоляцией комнат, защитой от читерства и локальной аналитикой.
- **Задачи:**
  1. Спроектировать 3-слойное решение (`Client`, `Server`, `Shared`) с общими иммутабельными контрактами.
  2. Реализовать многопользовательский SignalR Hub с серверными таймерами и 3 режимами игры (`Classic Speed`, `Team Battle`, `Knockout Elimination`).
  3. Построить адаптивный Blazor-интерфейс (desktop + tablet + smartphone) с переиспользуемыми компонентами и управлением состоянием.
  4. Обеспечить хранение квизов, учётных записей (RBAC) и результатов в SQLite с экспортом в CSV.
  5. Покрыть бизнес-логику, БД и Blazor-компоненты автоматическими тестами (`xUnit` + `bUnit`).

## Слайд 4. Архитектура решения и разделение слоёв
*(Вставить Mermaid-диаграмму из `README.md` или нарисованную схему в draw.io)*
- **`ArenaQuiz.Shared`**: Иммутабельные `record` DTO, функциональная монада `Result<T>`, чистый движок расчёта очков `ScoreEngine`, контракты `IGameHubClient`/`IGameHubServer`.
- **`ArenaQuiz` (Server)**: `GameHub`, потокобезопасный `GameRoomService` (`ConcurrentDictionary` + `System.Threading.Timer`), `ArenaDbContext` (SQLite), `AuthService` (RBAC), REST API контроллеры.
- **`ArenaQuiz.Client` (WASM)**: `GameStateContainer` + `CascadingValue`, `SoundService` (WebAudio API), 6 переиспользуемых компонентов и 5 страниц.

## Слайд 5. Механизм реального времени (SignalR Sequence)
*(Вставить Sequence-диаграмму из `README.md`)*
- Постоянное полнодуплексное соединение по WebSockets (`/gamehub`).
- Строго типизированный хаб `Hub<IGameHubClient>` гарантирует согласованность контракта на этапе компиляции.
- Клиент никогда не получает `CorrectOptionIndex` до окончания вопроса и не отправляет время ответа — время считает исключительно сервер.

## Слайд 6. Функциональное программирование и фишки C# / .NET 10
- **Иммутабельность:** Все DTO объявлены как `sealed record` с неразрушающей мутацией (`with`).
- **Чистые функции (`ScoreEngine`):** Детерминированный расчёт очков ($O(1)$), сортировка лидерборда ($O(P \log P)$), группировка команд ($O(P)$).
- **Монада `Result<T>`:** Методы `.Map()` и `.Match()` устраняют исключения для ожидаемых бизнес-ошибок.
- **Продвинутый Blazor:** `EventCallback<T>`, `CascadingValue`, шаблонный компонент `TemplatedMetricGrid<TItem>` с `RenderFragment<TItem>`.

## Слайд 8. Тестирование и качество (xUnit + SQLite + bUnit)
- **Модульные тесты (`ScoreEngineTests`)**: проверка формулы скорости, потолка серии (`+50%`), отсечения просроченных ответов, тай-брейков, CSV-экранирования.
- **Интеграционные тесты (`GameRoomServiceTests`, `QuizRepositorySqliteTests`)**: полный цикл игры, переподключение по `ReconnectToken`, выбывание в Knockout, SQLite In-Memory CRUD и RBAC.
- **UI-тесты компонентов (`BlazorComponentsBunitTests`)**: проверка кликов и `EventCallback`, отображения верного/ошибочного ответа, таймера и переключения команд.

## Слайд 9. Масштабирование и выводы
- **Горизонтальное масштабирование:** Вынос состояния из памяти процесса в Redis Backplane + Azure SignalR Service позволяет обслуживать 1,000+ одновременных игроков без потери сообщений.
- **Итоги:** Создано готовое к внедрению кроссплатформенное приложение с открытым исходным кодом, доказанной тестируемостью и полным соблюдением стандартов .NET 10.
